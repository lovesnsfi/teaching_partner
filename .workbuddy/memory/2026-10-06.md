# 2026-10-06 局域网沟通广播项目

## 完成工作
- 用 Electron 30 + Vue3 + Pinia + TailwindCSS 4 + ws 实现局域网聊天与屏幕广播软件（方案A WebRTC Mesh，无中心服务器）。
- 模块：UDP 广播发现(41234) / WebSocket 聊天+信令(41235) / desktopCapturer 屏幕捕获 / WebRTC Mesh 推流。

## 关键约定与踩坑（可复用）
- electron-vite 2.x 不自动探测入口，必须在 config 显式写 `build.lib.entry`（main 指向 electron/main.js，preload 指向 electron/preload.js）。
- 渲染层入口约定在 `src/renderer/index.html`（不是根目录），vue 源码放 `src/renderer/`。
- TailwindCSS 4 用 `@tailwindcss/vite` 插件，无需 tailwind.config，直接用 `@apply`。
- npm 安装后报 `Cannot find module @rollwind/rollup-win32-x64-msvc`（npm optional dep bug），需删 node_modules + package-lock.json 重装。
- 国内安装设 `ELECTRON_MIRROR=https://npmmirror.com/mirrors/electron/`，registry 用 npmmirror。

## 验证
- `npm run build` 通过，产出 out/main/main.js、out/preload/preload.js、out/renderer/。

## `npm run dev` 报错 "No electron app entry file found: out/main.js" 的修复（重要）
根因：electron-vite dev 先按 `package.json` 的 `main` 字段找入口，但默认产物是 `out/main/main.js`，路径对不上。连带还修了几处隐藏路径错误：
- `pkg.main` 改成 `out/main/main.js`（与 electron-vite SSR 产物名一致；dev 会先 build main 到该路径再启动）。
- electron-vite 对 main/preload 走 SSR bundle，固定产物名：main→`out/main/main.js`，preload→`out/preload/preload.js`，renderer→`out/renderer/`（不要自己设 fileName，会被忽略）。
- 主进程 `electron/main.js` 三处修正：
  - `preload` 路径 `join(__dirname,'preload.js')` → `join(__dirname,'../preload/preload.js')`
  - 渲染目录 `DIST = join(__dirname,'../dist')` → `join(__dirname,'../renderer')`
  - dev 环境变量 `process.env.VITE_DEV_SERVER_URL` → `process.env.ELECTRON_RENDERER_URL`（electron-vite 注入的是后者）
- **ESM/CJS 大坑**：根 `package.json` 不能写 `"type":"module"`。否则 electron-vite 把 main/preload 编成 ESM，Node 加载 `electron` 时 `import { app } from 'electron'` 报 "does not provide an export named 'BrowserWindow'"。改为 main/preload `build.lib.formats:['cjs']` 且去掉 type:module，产物用 `require('electron')` 解构，正常。
- 沙箱无图形显示，`electron.app` 为 undefined 属环境限制（process.type=undefined），真机有显示器则正常。

## Tailwind 改用纯工具类 + 去菜单（2026-10-06 续）
- 用户指出 Tailwind v4 不应使用 `@apply`（易踩坑），改为：基础样式写在 `src/renderer/style.css` 的 `@layer base` 里用**纯 CSS**（避免 unlayered 纯 CSS 优先级高于工具类导致 bg-blue-600 等失效），组件模板**全部直接写 Tailwind 工具类**，删除所有 `@apply` 与内联 `style=""`。
- 配色改用柔和 modern slate/blue 体系：顶部渐变 `from-blue-600 to-indigo-600`；设备/群条目卡片 `rounded-xl border` + 选中 `border-blue-500 bg-blue-50`；消息气泡 mine `bg-blue-600 text-white rounded-br-sm` / 对方 `bg-slate-100 rounded-bl-sm`；头像圆 `w-9 h-9 rounded-full bg-blue-100`。
- 去掉 Electron 自带菜单：`main.js` 导入 `Menu`，在 `app.whenReady()` 开头 `Menu.setApplicationMenu(null)`。
- 构建通过：renderer CSS 24.68kB、JS 260kB；组件均含直接工具类，无 @apply/style 残留（grep 验证 0 匹配）。
- 结论：**v4 项目里可用 `@apply` 给内置工具类，但为稳妥统一不用；基础重置必须放在 `@layer base` 内，否则 unlayered 规则会盖过工具类。**

## 无边框窗口 + 托盘驻留（2026-10-06 续）
- 需求：无边框窗体、Web 自绘最小化/正常(最大化切换)/关闭按钮、右下角托盘图标、点最小化或关闭只隐藏到托盘不退出、仅托盘右键菜单「退出」才真正退出。
- `electron/main.js`：`BrowserWindow` 加 `frame:false` + `icon`；`win.on('close')` 拦截——非 forceQuit 时 `preventDefault()` + `setSkipTaskbar(true)` + `hide()`；新增 `showWindow()` 恢复（setSkipTaskbar(false)+show+focus）。新增 IPC `window:minimize`/`window:maximize`(toggle)/`window:close` 均隐藏到托盘。`app.whenReady` 内 `new Tray(icon)` 设 tooltip、click→showWindow、`setContextMenu` 含「显示窗口」与「退出」(退出置 forceQuit=true 并 destroy LAN 后 app.quit())。`window-all-closed` 改为空（托盘常驻）。`Menu.setApplicationMenu(null)` 已去掉自带菜单。
- 托盘图标：`electron/icon.js` 运行时用 `nativeImage.createFromBuffer` + 自写 PNG 编码器（zlib.deflateSync + CRC32）画蓝底白心圆，避免依赖二进制资源文件；同时用作窗口 icon。
- `electron/preload.js`：新增 `windowMinimize/windowMaximize/windowClose`（`ipcRenderer.send`）。
- `src/renderer/App.vue`：顶栏加 class `drag-region`，右侧自绘三个 `win-btn`（– ☐ ✕），调用 `window.api.windowXxx()`；交互控件加 `no-drag`。
- `src/renderer/style.css`：纯 CSS 加 `.drag-region{ -webkit-app-region:drag }`、`.no-drag{ ...:no-drag }`、`.win-btn`（透明背景、hover 白雾、`.win-close` hover rose）。
- 已知限制：frame:false 后 Windows 默认无法拖窗口边缘缩放（maximize 按钮可全屏/还原）；如需边缘缩放需自实现 resize 命中区。
- 构建通过：main 17.1kB（含 icon.js）、preload 2.06kB、renderer CSS 25.25kB。
根因：主进程切到 CJS 输出后，源文件 `electron/main.js` 第 17 行仍残留 ESM 写法 `const __dirname = fileURLToPath(new URL('.', import.meta.url))`。CJS 下 `import.meta` 不存在、`fileURLToPath` 也未 import，且 `__dirname` 本就是 CJS 全局变量。直接删掉该行即可（已改为注释说明）。
结论：**CJS 输出时不要保留任何 `import.meta` / `fileURLToPath` / `URL`(相对路径) 写法**，路径一律用 CJS 内置 `__dirname` / `__filename`。

## 本地持久化改造完成（sqlite/JSON 兜底）
- 需求：聊天消息 + 设置项本地持久化（用户允许 sqlite 或其它方案）。
- 主进程：`electron/persist.js` 导出 `createPersistence(userDataDir)` —— **优先 better-sqlite3**（kv/groups/messages 三表，WAL），`import('better-sqlite3')` 失败则**自动降级 JSON 文件**（`lan-chat-data.json`，读-改-写整文件）。两者对外接口一致：`load()/saveSettings()/replaceGroups()/appendMessage()/updateMessage()`。消息单会话上限 400 条，超出删最旧；重启后 file 类消息规范化为非发送/接收中。
- `main.js`：whenReady 内 `persist = await createPersistence(app.getPath('userData'))`，注册 IPC `db:load`/`db:saveSettings`/`db:replaceGroups`/`db:appendMessage`/`db:updateMessage`。
- `preload.js`：白名单暴露 `dbLoad/dbSaveSettings/dbReplaceGroups/dbAppendMessage/dbUpdateMessage`。
- store：`init()` 改为从 `dbLoad()` 还原 settings/groups/messages（含把 selectedInterface/avatar/name 还原回主进程）；删除旧 `localStorage` 路径与 `STORE_KEY`/`loadState`/`MAX_MSG_PER_CONV`（常量保留复用）。新增内部方法 `_saveSettings()`（落设置）、`_persistGroups()`（落设置+整表替换群）、`_appendMsg(convId,msg)`（内存 push + 增量 `dbAppendMessage`）、`_updateMsg(convId,fileId,file,receiving)`（落文件完成态）。所有原 `this._persist()` 调用（16 处）按语义改接上述新方法：设置类→`_saveSettings`、群类→`_persistGroups`、发/收消息→`_appendMsg`、文件完成→`_updateMsg`。
- 构建坑与修复：**未装 better-sqlite3 时，persist.js 的 `import('better-sqlite3')` 被 Rollup 构建期解析报错**（`Rollup failed to resolve import "better-sqlite3"`）。修复：在 `electron.vite.config.mjs` 的 main `rollupOptions.external` 增加 `'better-sqlite3'`（与 `'ws'` 并列）；运行时该包不存在则 `import` 拒绝被 catch → 自动走 JSON 兜底，符合"或其它方案"。
- 结论：better-sqlite3 当前**未实际安装**，运行时走 JSON 文件持久化（已满足需求）。若日后要启用真 SQLite，需 `npm install better-sqlite3` 并用 electron-rebuild 按 Electron ABI 重编，再打包。
