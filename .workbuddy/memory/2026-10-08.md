- **修复「框选后调整选区时选区跳到左上角」**（`ScreenShot.vue`）：
  - **根因**：底图 `<img class="shot-bg">` 未设 `draggable="false"`，鼠标在它上面按下会触发**浏览器原生图片拖拽**，一旦进入 drag 状态，后续 mousemove 就不再派发给页面，我们的 move/resize 逻辑失去输入，选区状态被重置到初始值（表现为跳到 0,0）。另外 `onDown` 只在"新建选区"分支调了 `e.preventDefault()`，"移动/手柄"分支直接 return 没有阻止默认行为。
  - 修复：`<img draggable="false">` + CSS `-webkit-user-drag:none` + 根节点 `@dragstart.prevent`；`onDown` 开头统一 `e.preventDefault()`（所有分支都拦）。
  - 顺带修正选区高亮遮罩：上一版用「全屏压暗层 `.shot-mask` + `box-shadow: transparent` 挖洞」是**无效的**（透明阴影不会擦除已绘制的内容）。改为标准做法 —— 有选区时根节点背景透明，由 `.shot-sel` 自身的 `box-shadow: 0 0 0 9999px rgba(0,0,0,.45)` 压暗四周（大 spread 阴影不覆盖元素自身区域），`.shot-mask` 已删除。
  - 经验：Electron 透明遮罩窗口里放`<img>` 做底图时，必须 `draggable=false` + `preventDefault`，否则自定义拖拽必被原生拖拽劫持。
- **修复框选选区「点一下就跳 / 拖动中跳到左上角」（第二轮加固）** 两个独立根因：
  - **① 坐标系不匹配（主进程）**：遮罩层与鼠标坐标用的是**显示器尺寸** `display.bounds`（shotSource.width/height），但落盘的 PNG 是 `thumbnailSize` 按 ratio 缩小过的。高分屏（>2560×1440 或>1920×1080）时两者不等，`shot:confirm` 直接拿显示器坐标去crop PNG 会越界（`crop` 抛错或空白）。修复：`shotSource` 增存 `pngWidth/pngHeight`，确认时按 `sx = pngWidth/width`、`sy = pngHeight/height` 换算并对 `pw/ph` 做夹紧。
  - **② 拖拽状态残留（渲染层）**：若某个 `mouseup` 没被收到（例如在窗口外松开鼠标），`mode` 会一直残留，之后**任意一次鼠标移动都会继续改写选区**，看起来就是"点一下/移动一下就跳"。三道加固：
    - `onMove` 开头判断 `(e.buttons & 1) === 0` 则立即 `resetDrag()`——只在确实还有按键时才跟随鼠标；
    - `mouseup` 改为**捕获阶段**监听，并新增 `window.blur`、`document.mouseleave` 也调 `resetDrag()`；
    - 新增 `clampRange(v, lo, hi)`（`hi<lo` 时退化为 `lo`）替换原先的 `clamp(v, max)`：原写法在 `maxX()-o.width` 为负时会把值压到 **0**，这正是"跳到左上角"的直接来源。手柄命中容差 HIT 由 7 收紧到 5，减少误抓。
  - `onUp` 重命名为 `resetDrag()` 并集中处理复位逻辑。
