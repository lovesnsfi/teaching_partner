## npm run pack 报错——winCodeSign 符号链接权限问题

- 现象：`npm run pack` 在 winCodeSign 解压阶段失败，报错 `ERROR: Cannot create symbolic link : 客户端没有所需的特权`，对象是 `winCodeSign\...\darwin\10.12\lib\libcrypto.dylib` / `libssl.dylib`。
- 根因：electron-builder 用 7-zip 解压 `winCodeSign-2.6.0.7z`（含 macOS 的 .dylib 符号链接）时需要"创建符号链接"权限（SeCreateSymbolicLinkPrivilege）。当前用户非管理员、Developer Mode 关闭，默认无此权限 → 解压中止。日志开头的 "postinstall/install-app-deps" 提示是无关的通用信息。
- 检测（本机即用户机）：`whoami` 非管理员；`HKLM:\...\AppModelUnlock\AllowDeveloperMode` 为空（开发者模式关）。缓存位于 `C:\Users\YangBiao\AppData\Local\electron-builder\Cache\winCodeSign\`，已有 3 个 `.7z`（已下载）和若干空/半解压目录。
- 修复尝试（已证伪）：用项目内 `node_modules/7zip-bin/win/x64/7za.exe` 手动解压这三个 `.7z`，加 `-xr!*.dylib` 排除 macOS 符号链接、加 `-y`。解压本身成功（rcedit-x64.exe 就位）。
- **但该手动方案无效**：`npm run pack` 实测仍失败——electron-builder 每次运行都**重新随机生成缓存目录名**（实测 `432651555`→`539732279`/`674223307`，非确定性 hash）并尝试重新下载+解压，根本不会复用我手动解压的目录，于是再次撞同符号链接报错。故手动解压缓存不可行，必须从源头给"创建符号链接"权限。
- 真正可行的修复（二选一，均需用户一次操作）：① **以管理员身份运行终端**再 `npm run pack`（管理员默认有 SeCreateSymbolicLinkPrivilege，最稳、无需重启）；② 开启 **Windows 开发者模式**（设置→系统→开发者选项→开），普通终端即可建符号链接，但有时需注销/重启才生效。本机当前进程非管理员（ADMIN=False），无法从此处改系统设置或提权，故只能交由用户执行。
- 注意：图标相关配置（`package.json` 的 `build.icon`、`icon.js` 的 getAppIcon）本身正确；权限问题解决后打包即会嵌入 app.ico。

- **修复「删除的离线联系人重启后又出现」**：根因是上一轮加的 `_backfillContactsFromMessages()` —— 它扫描历史聊天记录，凡是没在 contacts 里的 `fromId` 都会补成联系人。由于早期设备 ID 每次启动都变，历史消息里散落着大量旧 id，用户删掉的那些正好被回填重新加回。

  - `_backfillContactsFromMessages()` 跳过墓碑中的 id，并且**只在 `contacts` 为空时才回填**（恢复其原本"自愈"定位，不再每次启动翻历史）。

- **确立并实现「联系人即设备 + 删除即清空会话记录」模型**（用户提出的思路，评估合理后执行）：核心语义澄清 —— 联系人身份绑定**设备**（稳定 machine ID + 主机名），IP/昵称变化都不影响唯一性；右键删除离线联系人的真实含义是「**清除与该设备的会话记录**」，而非「删除这个人」。因此对方之后重新上线会被 UDP 发现重新并入列表（同一台设备），只是不再有历史记录 —— 这与 WeChat「清空聊天记录」的心智模型一致，且不会造成"人明明在线却看不到"的割裂。
